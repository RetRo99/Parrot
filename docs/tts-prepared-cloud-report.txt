Step 0: how a book is identified across devices and mapped to the local prepared
store:
  cloud_books.id IS the client's library book id - a random UUID the client
  chooses, with the server default removed
  (20261001000000_parrot_cloud_client_book_ids.sql:1-3 and :32-33); the source
  content hash is only a duplicate hint (:26-31). The change applier states the
  same mapping and looks the book up by it
  (ParrotCloudBookFileChangeApplier.kt:37-39), so after a second device syncs both
  devices hold the SAME libraryBookId for the same book. The prepared store hashes
  that id with the server id:
  File(root, hash("${serverId?.length ?: -1}:$serverId$bookId")) then
  hash(chapterHref) (feature/reader/ui/.../tts/TtsPreparedStore.kt:61-63), fed in
  production from epubPublication.bookUuid and epubPublication.serverId
  (.../navigator/AndroidTtsController.kt:823-827), where for a library book
  bookUuid is the libraryBookId and serverId is LOCAL_SERVER_ID = "local"
  (base/.../server/ServerType.kt:7). So the chapter folder is the identical path
  on both devices, sha256("5:local" + libraryBookId)/sha256(chapterHref), which is
  what makes a cloud download installable on the second device with no remapping.
