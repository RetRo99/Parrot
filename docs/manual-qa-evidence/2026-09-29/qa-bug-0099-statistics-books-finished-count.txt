# QA-BUG-0099 — unfinished book reported as finished

- **Observed:** 2026-09-29, approximately 21:00 CEST, Samsung `RFCWC0SSVDM`.
- **Device/build:** SM-S921B (Galaxy S24), Android 16/API 36, One UI 8.0; `com.retro99.parrot` 0.4.5 (21), target SDK 36, debug APK SHA-256 `aedfaa942c52eb4adcbd55160cbb08a323ece49ee55a797ee3075d5ce80e8a39`, built from source `cda04f742fc6f874249418f3188edae7ed8560a8`; Parrot PID `29406`.
- **Preconditions:** Guest mode; imported the repository's public-domain `Pride and Prejudice` EPUB. Read for about 6m 19s, advanced to the book's opening text, then used Back to close Reader. The Book Detail screen showed `Reading Progress 1%` and `Continue reading (1%)`.
- **Exact reproduction:** Open Statistics after closing the Reader. In the Week dashboard's glance card, observe `1` above the label `Books finished`. The full Statistics screen showed 6m and 1 session for the current week.
- **Expected:** A book at 1% progress is not finished; the finished-books metric should remain zero unless the book reaches the product's completion threshold. If the metric intends to count any book with reading history, its label must not say “finished.”
- **Actual:** The card showed `1 Books finished` for the one local EPUB despite Reader reporting 1% progress. This is misleading user-facing Statistics.
- **Frequency:** Confirmed once on the Samsung. Source query structurally counts every distinct `book_uuid` with a reading session in the date range, regardless of progress/completion.
- **Evidence:** [`case-421-profile-A-statistics.png`](case-421-profile-A-statistics.png) shows the 6m / 1 session totals and `1 Books finished`; [`case-421-profile-A-reader-after-reading.png`](case-421-profile-A-reader-after-reading.png) retains the post-reading Reader page; Book Detail's accessibility snapshot after Back reported 1% and `Continue reading (1%)`. PID-scoped logcat recorded `book_opened`, a successful `reader_position_save`, and `book_closed` with 378930ms duration and 1% progress. Source: `ReadingSession.sq:getDistinctBooksReadInDateRange` counts `COUNT(DISTINCT book_uuid)` for any session; `StatisticsScreen.kt` presents that value using `statistics_glance_books_finished`.
- **Profile caveat:** This observation was made in built-in `Default`, not the intended disposable Profile A. It is recorded as a concrete Statistics defect but does not by itself satisfy the requested case-421 disposable A/B isolation variant.
- **Root cause:** The dashboard presents a count of distinct books with any recorded reading session as a count of finished books. The session schema has progress values, but this aggregation does not use them.
- **Affected files:** `lib/database/implementation/src/commonMain/sqldelight/com/retro99/database/implementation/ReadingSession.sq`; `feature/statistics/ui/src/commonMain/kotlin/com/retro99/statistics/ui/StatisticsScreen.kt`; `translations/src/commonMain/composeResources/values/strings.xml` (display label). The latter contains unrelated uncommitted user changes; any fix must preserve them.
- **Fix reference / commit:** None at finding time. Record this entry before changing product code.
- **Retest:** NOT RUN; fix and Samsung retest required before case 421 can be signed off. Analytics/diagnostics coverage for the metric was not independently verified by this observation; Firebase Analytics ingestion is waived.
