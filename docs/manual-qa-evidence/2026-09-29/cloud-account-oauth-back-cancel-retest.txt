# Cloud Account route and Google OAuth Back/cancel Samsung evidence

- **Run/device:** 2026-09-29, physical Samsung `RFCWC0SSVDM`, model SM-S921B, Android 16/API 36, One UI 8.0 (`ro.build.version.oneui=80500`), build `BP4A.251205.006.S921BXXSGDZG1`, gesture navigation. Package `com.retro99.parrot` 0.4.5 (21).
- **Installed candidate:** debug APK SHA-256 `e30ad041567e2e043bed08e5fc6662634abd86c3a13b717a057373212e8a3c3e`, source commit `9cd6ff56ee48f8297e0cd2ebc095a3313d205f3d`; installed with `adb install -r`, preserving app data. No uninstall, clear-data, profile switch, or server fixture mutation.
- **Safe entry:** Launched Parrot from the launcher. It opened the saved-book unauthenticated-server prompt; selected Close only and did not tap Retry. Navigated Settings → Sync & Backup. The Cloud Account form was signed out, empty and ready; no email/password was entered. Screenshots: [form before action](cloud-account-before-oauth-cancel.png), [current form after Back cancellation](cloud-account-oauth-immediate-back.png).
- **Case 357 route evidence:** At `06:35:15 CEST`, local DebugAnalyticsManager recorded exactly one `sync_and_backup_screen_viewed` with `source_screen=app_settings`, `entry_point=sync_backup_row`, plus one visible `sync_and_backup_route` breadcrumb. Session restoration emitted one attempt and one success (`result_code=signed_out`) with correlated start/stage/terminal breadcrumbs. The signed-out form rendered. This is local debug output, not Firebase delivery.
- **Case 367 first attempt (not the cancellation retest):** At `06:36:17`, Continue with Google emitted one attempted event (`is_retry=false`) and `oauth_start`; Samsung Browser displayed the debug build's device-loopback endpoint error rather than a provider authorization page (see [endpoint observation](cloud-account-google-oauth-debug-endpoint.txt) and [browser screenshot](cloud-account-oauth-start.png)). The operation ultimately emitted `cloud_account_operation_failed` with `reason_code=oauth_timed_out`, `duration_ms=388125`; the form displayed its generic retry banner ([screenshot](cloud-account-oauth-back-result.png)). Because the provider page was unreachable and the external page remained open for several minutes, this is recorded as a timeout, not a cancellation result. No credentials were entered or authorization completed.
- **Case 367 immediate Back retry:** At `06:44:47`, tapped Continue with Google again; the attempt was correctly marked `is_retry=true`. Pressed system Back after about 1.2 seconds on Samsung Browser. Parrot returned to the signed-out form in about 1.8 seconds with no error banner, no loading spinner, empty credentials, and no partial authenticated state. Local DebugAnalyticsManager recorded exactly one `cloud_account_operation_cancelled` with `reason_code=oauth_cancelled`, `is_retry=true`, `duration_ms=1806`; the operation had one correlated start, `oauth_start` stage and terminal cancelled breadcrumb. No local non-fatal/exception or fatal marker appeared for this cancellation. The event's payload did not include account, profile, provider or URL data.
- **Retest disposition:** PASS for the Samsung app-side external-activity/system-Back cancellation path and retry state. This does not pass the provider-page cancellation variant: the actual Google authorization page is unreachable in this debug build, so case 366 and provider-page cancellation remain BLOCKED by QA-BUG-0086. Host tests separately verify typed `access_denied` and provider failure distinction.
- **Provider boundary:** `DebugAnalyticsManager` logs are local only. Firebase Analytics ingestion is waived; Crashlytics delivery was not exercised and remains unverified. Ordinary cancellation generated no exception report.
