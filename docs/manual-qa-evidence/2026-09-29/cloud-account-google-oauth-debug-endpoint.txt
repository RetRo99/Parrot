# Samsung debug-build Google OAuth endpoint observation

- **Run:** 2026-09-29, Samsung OAuth launch preflight for Cloud Account cases 366–367 and 778.
- **Device:** physical Samsung `RFCWC0SSVDM`, model SM-S921B, Android 16/API 36, One UI 8.0 (`ro.build.version.oneui=80500`), build `BP4A.251205.006.S921BXXSGDZG1`, gesture navigation; package `com.retro99.parrot` version 0.4.5 (21).
- **Build:** debug APK `androidApp/build/outputs/apk/debug/androidApp-debug.apk`, SHA-256 `e30ad041567e2e043bed08e5fc6662634abd86c3a13b717a057373212e8a3c3e`, app source commit `9cd6ff56ee48f8297e0cd2ebc095a3313d205f3d`; installed with `adb -s RFCWC0SSVDM install -r`, no uninstall/data clear.
- **Pre-state:** App was opened from launcher. It showed the existing unauthenticated-server prompt; tester selected Close only (never Retry), returning to Books. Settings → Sync & Backup opened the signed-out Cloud Account form. Email and password fields were empty. No cloud/account credentials were entered.
- **Action and actual:** At approximately 06:36 CEST, tapped “Continue with Google.” Samsung Browser (`com.sec.android.app.sbrowser/.SBrowserMainActivity`) opened a page at host `127.0.0.1`; the visible page said “This site can't be reached” and “null is unreachable.” No provider authorization page/account chooser appeared and no authorization was performed. Screenshots: [signed-out form before action](cloud-account-before-oauth-cancel.png), [browser result](cloud-account-oauth-start.png).
- **Local instrumentation at initial capture:** DebugAnalyticsManager logged one `cloud_account_operation_attempted` for `operation=cloud_authentication`, `entry_point=google_button`, `auth_method=google`, `mode=sign_in`, then a correlated `oauth_start` breadcrumb. This is local DebugAnalyticsManager output, not Firebase delivery. At initial capture the operation was still in progress; its later timeout and separate immediate Back/cancel retry are recorded in [the Samsung route/cancel retest](cloud-account-oauth-back-cancel-retest.txt).
- **Source/config cross-check:** `androidApp/src/debug/AndroidManifest.xml` and the generated merged debug manifest provide a Supabase URL with scheme `http`, host `127.0.0.1` (loopback), plus a non-empty publishable-key metadata value. Only presence/length was inspected; key bytes and full URL were not printed or retained. The production/main manifest uses a non-loopback HTTPS host; this run does not establish its reachability or authorize switching this device/build to production.
- **Host fixture check:** Host process inspection found Docker holding a listener on port `54321`, but a local `/auth/v1/health` request timed out after three seconds; `adb -s RFCWC0SSVDM reverse --list` showed no active reverse mapping. A listening socket alone is not evidence that the local Supabase auth service is usable. No reverse mapping or endpoint change was applied.
- **Expected:** A reachable, authorized test Supabase endpoint should return a provider authorization page so a user can safely choose Back/cancel or an explicitly authorized sign-in fixture.
- **Disposition:** QA-BUG-0086 is CONFIRMED for the installed debug variant; provider-flow test 366 and provider-page cancellation variant 367 are BLOCKED pending an authorized reachable QA endpoint. Do not treat this loopback error page as a valid provider cancellation or success. It is safe to return to the app with Back and separately inspect how the pending operation is finalized; any such observation is scoped to local app-side dismissal handling only.
- **Privacy/scope:** No email, password, OAuth code, token, provider account, full endpoint, key value, real profile identifier/name, or cloud account data is recorded. The original app profile and unauthenticated server fixture were preserved.
