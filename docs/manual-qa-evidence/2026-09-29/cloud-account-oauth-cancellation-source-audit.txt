# Cloud Account OAuth cancellation source audit

- **Audit date:** 2026-09-29.
- **Device/build context:** required Samsung `RFCWC0SSVDM`, SM-S921B, Android 16/API 36, One UI 8.0 (`ro.build.version.oneui=80500`), build `BP4A.251205.006.S921BXXSGDZG1`; installed package `com.retro99.parrot` 0.4.5 (21), previously verified APK SHA-256 `d1f5202462a20294aa5a8c3fd227266deace01e661dfb37c3973fea0b0fafe06`; source before this finding's fix: commit `b23eb4ff` (full commit hash in repository history). No browser/OAuth flow was launched and no credentials entered.
- **Cases:** 367, 731, 778; shared 742 and 748–749.
- **Source trace:** `CloudOAuthCallbackRegistry.handleRedirect()` accepts `parrot://auth/callback`; when the query has no nonblank `code`, it calls `deferred.completeExceptionally(CloudOAuthException(...))`. `CloudOAuthException` is private and extends ordinary `Exception`, not `CancellationException`. `SupabaseCloudAccountDataRepository.signInWithGoogle()` propagates this exception from `awaitCode()`. `CloudAccountOperationTelemetry.execute()` emits a cancelled terminal only for `CancellationException`; the OAuth exception goes through `OperationFailed` and the caller's fixed `authentication_failed` reason. `CloudAccountViewModel.signInWithGoogle()` calls generic `showError()` after a thrown operation, so the signed-out form gets the generic error state. Its unexpected-exception predicate does not report this class as Crashlytics non-fatal.
- **Expected safe classification:** explicit user/provider `access_denied` or callback cancellation maps to a stable OAuth-cancel type, one `cancelled` event and matching correlated breadcrumb, no non-fatal; timeout/provider failures remain failed with bounded reason codes. Do not carry provider error descriptions, callback URL, code, token or credentials into logs/Analytics.
- **Evidence boundary:** This deterministic source path is the basis for QA-BUG-0085, not an executed runtime/device result. A safe Samsung retest may start OAuth and cancel before entering credentials; successful auth, Firebase event ingestion and Crashlytics delivery remain separate.
