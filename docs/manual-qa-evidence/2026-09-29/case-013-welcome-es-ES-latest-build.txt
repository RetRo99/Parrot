## Steps and result

1. Built from a detached clean worktree at the committed source revision, not from the main working tree with unrelated uncommitted user changes. The first build attempt stopped before task execution because the worktree lacked ignored `local.properties`; copying the existing SDK-only local configuration resolved this environment setup issue. `:feature:login:ui:testAndroidHostTest` passed 37/37 and `:androidApp:assembleDebug` succeeded (593 actionable tasks; 462 executed, 131 cached).
2. Installed the hash-identified APK without clearing data again and launched Parrot with `es-ES` active. Package version/code remained 0.4.5 (21); installed `base.apk` hash matched the build artifact.
3. Expected first-run Welcome after the approved data clear. The Welcome screen was visibly usable and showed the expected English `Get Started` and `Browse without account` actions. All visible app copy in the captured Welcome screen was English; no clipping or overflow was seen. The UI hierarchy automation returned zero Compose elements/timed out, so visual inspection used the direct Samsung screenshot rather than treating the automation timeout as an app failure.
4. Restored the original `en-GB` locale and removed the temporary Spanish language entry. The app is left at first-run state because the authorized Parrot data clear removed its previous profiles/session; notification permission remains denied.

**Functional:** PASS for the Welcome-under-`es-ES` variant; full case 13 remains PARTIAL because the other routes sampled in the historical locale run were not revisited on this current build.
