## Feasibility evidence

- `ReaderViewModel.initTts()` waits for a current EPUB locator, calls `ttsController.hasReadableContent()`, loads available device voices, sets the Reader state to `isTtsReadAloud`, and enables sentence playback when the saved TTS setting is on. This path does not require an authenticated audiobook or server ReadAloud session. `setTtsEnabled()` applies the setting and emits the bounded `tts_enabled_changed` event; `AndroidTtsController` records playback attempt/terminal outcomes with `media_type=ebook` and correlated diagnostic context.
- `ReaderScreen` renders the ReadAloud Play/Pause controls when readable EPUB content is available and TTS is enabled. This proves source reachability, not disposable-profile import or runtime behavior for case 417.
- The physical Samsung previously completed on-device TTS on a retained local EPUB using the System voice: local `tts_playback_operation` emitted `attempted` then `succeeded` (`media_type=ebook`), the player displayed Pause, and EPUB progress advanced. The active profile role/name was not retained in that sanitized TTS record, so it cannot prove that this occurred in the case-417 disposable profile. `POST_NOTIFICATIONS` denial produced the expected ordinary `cancelled(reason_code=permission_denied)` result; after a temporary permission grant the run reached actual playback and restored the captured denied baseline. See [Samsung TTS run](tts-samsung-normal-path.txt).
- A controlled local EPUB was successfully imported through Parrot's file picker in the earlier Samsung guest journey; see [case 3/5](../2026-09-26/case-003-guest-cold-start-run.txt). That does **not** establish import/read/TTS inside the disposable profile used for case 417; this profile-specific fixture setup remains unverified.
- Profile switching is observable: `AppSettingsViewModel.selectProfile()` runs the switch operation and checks that the selected active profile was applied. Home shows its mini-player outside Reader when now-playing information exists. Reader hides Home bottom navigation. Reader close does not explicitly stop TTS in the inspected path, and the TTS engine is application-singleton, but whether actual PLAYING survives leaving Reader and a profile switch is unknown and must be checked on-device. Do not infer stop-or-continue from source alone.
