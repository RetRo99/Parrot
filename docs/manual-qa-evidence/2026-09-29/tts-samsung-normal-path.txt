## Executed steps and observations

2. Enabled TTS from the Reader controls. The UI exposed Play and Voice settings. Later disabled TTS; local output contained one `tts_enabled_changed(is_enabled=true)` and one `false` event.
3. Opened Voice settings, observed the System voice selected and available device-voice choices, then used its Back control to return to the Reader. One local `tts_voice_settings_opened` event was present.
4. Started TTS while notification permission was denied. Android showed its notification-permission prompt; tapped **Don't allow** (a denial, not prompt cancellation). The first operation emitted one correlated `attempted` → `cancelled(reason_code=permission_denied)` pair. A second start while still denied emitted the same bounded pair. No exception/non-fatal was expected or observed for ordinary permission denial.
5. Temporarily granted `POST_NOTIFICATIONS` with ADB for the normal playback check. A subsequent Reader-control operation emitted a matching `attempted` → `succeeded` pair (`action=controls`, `is_retry=false`, `media_type=ebook`, duration 1,899 ms). The player displayed Pause; the EPUB position advanced while TTS highlighting was visible. A content-minimized player UI crop is [here](tts-player-controls-only.png); progress changed from [Page 26/64, 48%](tts-page-progress-before.png) to [Page 28/64, 49%](tts-page-progress-during.png). The original full-page screenshots are not linked in this evidence record.
6. Used Reader navigation and Voice Settings/Back; one `tts_voice_settings_opened` event was observed. Two foreground resume operations also produced bounded, correlated attempt/success pairs. A separate explicit pause/resume freeze-and-restart comparison was not completed, so case 255 remains partial.
7. Returned the Reader to Page 26/64 (48%), disabled TTS, and restored the original Books `Readaloud` filter. The final Books state is [shown here](tts-filter-restored-samsung.png). App data and the retained EPUB were not deleted or modified.
8. Restored notification permission to the captured baseline using `pm revoke`, clearing only `user-fixed`, and setting `user-set`; final state was again `granted=false`, `USER_SET|USER_SENSITIVE_WHEN_GRANTED|USER_SENSITIVE_WHEN_DENIED`, AppOp `ignore`. No Firebase Analytics debug property was set.
