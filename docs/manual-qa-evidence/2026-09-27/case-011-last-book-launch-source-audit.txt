Screen/action inventory and case mapping
- App Settings → Reading → “Open last book on launch” switch: on/off and persistence are cases 11, 12, 424, 436, 719; failure/final persistence variants are case 719. `AppSettingsViewModel` persists `PreferencesKey.OpenLastBookOnLaunch` then logs `open_last_book_on_launch_toggled`; on source audit, no attempt/commit breadcrumb surrounds `putBoolean`.
- Cold app start with preference enabled and a qualifying current-book record: cases 11, 518, 519, plus lifecycle/process recovery cases 461 and 607. Entry goes Splash → Home and then the startup reader replacement event selects Books/Reader.
- Enabled preference with no current-book record: case 12. Expected route is normal Home/Books without an error or empty Reader.
- Reader loading, close while loading, usable content, initialization error/retry and publication-open error: cases 138, 166, 474, 485, 595 and 612. The extension variants 518–519 are the target-unavailable/missing-file startup recoveries.

Audited implementation paths
- `HomeNavigationViewModel.init` invokes `checkOpenLastBookOnLaunch()`. If the preference is false it returns silently; if enabled with no current-reading model it also returns silently. If a model exists, `ContinueReadingLaunched(bookUuid)` is logged before `NavigateToReaderReplacing` is emitted.
- `ContinueReadingLaunched` exposes only `book_uuid`; `AnalyticsParameterSanitizer.SAFE_STRING_KEYS` intentionally rejects this key. Thus current provider delivery has no useful dimensions. It does not represent a successful usable reader open.
- `ReaderViewModel.initializeReader()` calls `error.log(...)` for initialization result failures. `openPublication()` logs `BookOpenFailed` and sets the Reader error state on publication service failure, but that branch does not invoke the unexpected-error reporter. `BookOpened` logs after `openPublication()` succeeds, but carries no source/entry-point dimension.
- `ReaderViewModel.close()` updates `CurrentlyReading` only if the session duration reaches `MINIMUM_READING_DURATION_MS`; `onCleared()` does not persist the current-book reference. This motivates suspected QA-BUG-0026, not a confirmed runtime finding.

Audit dispositions
- **Confirmed instrumentation gap:** QA-BUG-0025 — telemetry is logged before actual content is usable, identifier-only parameters are sanitized away, no last-book terminal success/failure exists, and one publication failure boundary lacks exception reporting.
- **Suspected functional gap:** QA-BUG-0026 — abrupt process termination may bypass the only currently-reading update. This is unconfirmed pending an on-device case-11 run.
- Cross-app/cross-device synchronization was not inspected or tested.
