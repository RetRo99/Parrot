Source trace and findings (no destructive server action performed)
- `feature/home/ui/src/commonMain/kotlin/com/retro99/home/ui/navigation/HomeNavigation.kt` routes `HomeDestination.ServerManagement` to `ServerManagementScreen` and supplies `onBack`/`onNavigateToLogin` callbacks.
- `ServerManagementScreen.kt` renders a loading spinner, an empty state, or cards. The card always exposes Remove; it exposes Logout only for `ServerAuthState.Authenticated`. There is no Login/Retry button for `NotAuthenticated`, `TokenExpired` or `AuthenticationFailed`, despite the `OnLoginClick` intent and test cases 444/448/449.
- The Remove icon dispatches `OnRemoveClick` immediately. No confirmation dialog or cancel route exists, despite case 447's expected confirmation and case 726's cancellation variants.
- `ServerManagementViewModel.observeServers()` sets `isLoading=false` only on a successful combined emission and has no catch/error state. `ServerManagementViewState` has only `isLoading` and `servers`.
- Only `server_add_attempted` is emitted for Add Server after fix `107d017c`. There is no server-management screen-view event. `ServerLoggedOut` and `ServerRemoved` events are logged before their registry mutations. The `ServerAdded` event definition is currently unused; successful Login has a separate `login_succeeded` event.
- `ServerManagementViewModel` launches logout/remove without catching operation exceptions or exposing a retryable error. In `ServerRegistryImpl`, `clearCredentials` mutates the in-memory credential map before writing preferences; `removeServer` mutates both in-memory maps before writing preferences. Neither operation rolls its maps back if persistence throws.
