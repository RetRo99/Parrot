- Samsung serial: RFCWC0SSVDM; model SM-S921B; Android 16/API 36; One UI 8.0.

- Installed package: `com.retro99.parrot` 0.4.5 (21), debug, source commit `eead19774c367f93675e5d775cc7ad7a5f038e4b`.
- APK SHA-256 local and pulled from Samsung: `059d4d881adb604310d8301c8de47cd979616d3f9738d0dcfdd58d90ced7620b`.

Preconditions and steps
1. Explicitly targeted serial `RFCWC0SSVDM`.
2. Uninstalled only `com.retro99.parrot` (authorized first-install reset); installed the current debug APK with ADB. Package `firstInstallTime` and `lastUpdateTime` both became 2026-09-26 17:56:22.
3. Launched the package from its launcher activity; made no app selections and granted no permission.
4. Captured the visible Welcome screen: `case-001-first-install-welcome.png`.

Expected / actual
- Expected: Splash followed by Welcome, with Get Started and Browse without account.
- Actual: Startup completed to the Welcome screen with both actions and the expected reading/audio/server feature content; no dialog or loading state remained. No app permission prompt appeared. `POST_NOTIFICATIONS` is `granted=false`; package runtime-permission section showed no granted runtime permissions.
- The automation helper timed out trying to locate visible `Get Started`, and its UI hierarchy dump timed out, while the subsequent screenshot visibly showed the label. This is recorded as a UI-automation selector limitation, not an app failure.
- The Welcome screenshot also appears to lack the expected DEBUG badge although the installed APK is marked `DEBUGGABLE`; this observation is separately recorded as QA-BUG-0011 and does not alter case 1's functional assertion.
