# QA-BUG-0073 — Android file-logger write failures are suppressed (source audit)

- **Date:** 2026-09-28.
- **Status at audit:** SUSPECTED from source; no write failure has been induced on device or in a host test.
- **Device/build context:** Physical Samsung `RFCWC0SSVDM`, SM-S921B, Android 16/API 36, One UI 8.0; Parrot `com.retro99.parrot` 0.4.5 (21), current PID `21569`, installed APK SHA-256 `310dda0fdc9201b2815e0d855afb94e677b15d496b192087f8d183723868936e`, source commit `85041fee0ab5b0431c5361429dedb3bdb6be2e27` plus unrelated pre-existing changes. File logging is OFF and both app log files were absent at audit time; no logs were read or changed.
- **Exact source observation:** `lib/analytics/implementation/src/androidMain/kotlin/com/retro99/analytics/implementation/AndroidFileLogger.kt`, `appendToLogFile()` lines 68–77 catches all `Exception` from rotation/append and intentionally ignores it. `rotateLogFile()` lines 80–90 similarly catches and attempts deletion without reporting the failure. `FileLogger.log()` returns `Unit`, so callers cannot observe a write result. `DebugAnalyticsManager.logBreadcrumb()` and `AnalyticsManager.logBreadcrumb()` call the logger after preference checks; the file logger has no diagnostic callback, and recursively reporting an error through that same file would be unsafe.
- **Potential user impact:** If an enabled file logger cannot append/rotate (for example, an I/O exception or exhausted/unavailable storage), the preference can remain ON while diagnostics silently stop or become incomplete; a user may later find an empty/incomplete share file. This is not a reproduced runtime failure.
- **Expected:** Keep diagnostic writes best-effort and non-crashing, but expose/report a bounded non-recursive failure outcome so logging failure is not silently indistinguishable from success.
- **Frequency:** Every exception in the audited write/rotation catch path is suppressed by source; observed runtime frequency is unknown.
- **Safe-fixture blocker:** No controlled Android `filesDir` write-failure fixture is available. Do not fill device storage, modify app-private files, chmod app paths, or otherwise corrupt the retained Samsung profile/app data to induce it. Required verification is blocked pending a safe injected Android FileLogger failure seam/test fixture.
- **Evidence:** This sanitized source audit. No payload, file content, private path, account/profile/book identifier or credential is retained.
- **Fix reference / commit:** None; no fix attempted. Keep SUSPECTED until a deterministic failure test confirms the user-visible silent loss and the error-reporting design is safely tested.
