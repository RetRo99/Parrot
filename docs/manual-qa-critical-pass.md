## Critical-pass completion criterion

The critical pass is complete only when each reachable journey below has evidence-backed Samsung execution of its happy path, Back/cancel path, one meaningful failure/retry path, and relevant local persistence; every discovered high-impact defect is recorded before a focused fix, host-checked, Samsung-retested, and committed; and there is no unresolved confirmed crash, local data loss/leak, unauthorized account action, stuck recovery, or broken core reading/playback flow. Each case retains separate functional, Analytics, and diagnostics results with device/build/evidence references. Existing results may be carried forward only when their build and code still cover the current path.

Firebase Analytics ingestion remains waived; local debug events are acceptable app-side evidence but are **not** delivery evidence. Crashlytics delivery and symbolication remain required: completion needs a controlled representative non-fatal received with useful context and a symbolicated stack on a Firebase-enabled QA build. Any required critical path still blocked by a fixture or access dependency makes this pass **incomplete**, not PASS. Full 779-case completion remains a separate objective.
