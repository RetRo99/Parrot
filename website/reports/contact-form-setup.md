# Contact form setup (not deployed)

The static support form POSTs without JavaScript to a Cloudflare Pages Function.
It sends plain-text messages through Resend from `rok@parrotapp.dev` to
`rok@parrotapp.dev`, with the visitor address as Reply-To. Recipient and subject
are server-controlled. No automatic reply or attachments are sent.

## Cloudflare configuration, when launch is approved

Use a Git-integrated Pages deployment or Wrangler deployment supporting Functions;
drag-and-drop static asset upload alone does not deploy this handler. Keep project
root `website`, production command `npm ci && npm run build`, output `dist`.
The `functions/` directory is at that project root, not inside `dist`.

1. Create a Cloudflare D1 database for rate-limit counters.
2. Run `functions-schema.sql` against that database via its Console or Wrangler.
3. In Pages Settings → Bindings, add D1 binding **CONTACT_DB**.
4. In Settings → Variables and Secrets, add encrypted secrets:
   - **RESEND_API_KEY**: the domain-scoped sending key, never a public build variable.
   - **CONTACT_RATE_SALT**: a random secret of at least 32 bytes, e.g. generated by
     `openssl rand -hex 32` locally. Do not commit it.
5. Redeploy after changing bindings/secrets. Configure preview environments
   independently; do not give a publicly accessible draft deployment sending keys.

The handler fails closed if secrets, the database or Cloudflare's client IP header
are absent. `astro preview` serves static assets only: it does not execute Pages
Functions. Unit tests execute the real handler with mocked database/email delivery;
no live email was sent. Live delivery and D1 binding verification remain launch checks.

## Abuse protection / data handling

- Same-origin POST, bounded streaming body, server-side email/message validation,
  hidden honeypot and atomic D1 limit of five attempts per IP/hour.
- The hourly IP key is HMAC-derived with a private salt; raw IPs and message content
  are not saved to D1. Stale rows are removed on subsequent valid form requests;
  add scheduled cleanup if physical expiry must happen even without traffic.
- No request bodies or provider responses are logged by the handler. Cloudflare,
  Resend and Gmail have their own processing/log/retention rules.
- This is basic spam protection, not bot-proof. Distributed abuse needs additional
  edge limits or a separately approved challenge; no CAPTCHA/third-party scripts
  have been added.
- A failed delivery attempt consumes quota. A timeout can mean uncertain delivery;
  retries can produce duplicates. Success means provider acceptance, not guaranteed
  inbox delivery.
